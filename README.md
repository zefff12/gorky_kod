# Ассистент задач и встреч

Голосовой помощник, которому можно просто сказать: «Напомни завтра в 10 позвонить Ивану»,
«Что у меня на этой неделе?» или «Когда у меня была встреча с Иваном?» — и он поймёт,
запишет, найдёт и ответит голосом. Если чего-то не хватает, переспросит: «На какое время
поставить встречу?»

Делал как тестовое задание.

- Демо: https://voice-assistant-vohg.onrender.com
- Код: https://github.com/zefff12/gorky_kod

> Хостинг бесплатный, поэтому первый заход после долгого простоя может открываться
> до минуты. Дальше всё работает быстро.

## Как запустить

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
.venv\Scripts\activate        # на macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

Открываем http://localhost:8000 в Chrome, Edge или Safari. Сначала будет страница входа —
можно зарегистрироваться или нажать «Продолжить без регистрации». Дальше жмём на микрофон
(или Ctrl+Пробел) и говорим. Писать текстом тоже можно, это работает в любом браузере.

Чтобы погонять ассистента на данных из задания, в меню профиля (шестерёнка внизу слева)
есть «Загрузить тестовые данные» — подтянется вся тысяча записей из CSV.

Через Docker:

```bash
docker build -t voice-assistant .
docker run -p 8000:8000 voice-assistant
```

Тесты (их около 250, ни сеть, ни ключи не нужны):

```bash
pip install -r requirements-dev.txt
pytest
```

Настройки лежат в `.env.example`. Ключ для LLM необязателен: без него всё работает на
встроенных правилах.

## Что умеет

**Задачи и напоминания.** «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно
отправить отчёт», «Поставь задачу купить билеты до конца недели», «Купить молоко». Если не
сказать, когда, ассистент спросит «Когда и во сколько?» — можно ответить «без срока».

**Встречи.** «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с
дизайнером», «Созвон с клиентом послезавтра с 14 до 16». Если на это время уже что-то есть,
ассистент предупредит и предложит выбрать другое.

**Что запланировано.** «Что у меня сегодня?», «Какие планы на завтра?», «Покажи встречи на
следующей неделе». Понимает и короткие продолжения: после «Что у меня сегодня?» можно
сказать «а на завтра?», после «Какие встречи на неделе?» — «а задачи?».

**Поиск старых записей.** «Найди задачу про презентацию», «Когда у меня была встреча с
Иваном?», «Я когда-то ставил задачу по договору, найди её». Ищет не по точному совпадению:
«контракт» найдёт «договор», «слайды для выступления» — «Подготовить презентацию», опечатки
распознавания вроде «презинтация» тоже не мешают.

**Изменения голосом.** «А перенеси её на понедельник», «Переименуй её в Созвон с Иваном»,
«Отметь её выполненной», «Удали встречу с дизайнером» (переспросит перед удалением). Если
подходит несколько записей, покажет список и поймёт «вторую».

**Повторы.** «Каждый понедельник в 10 планёрка», «по будням в 10 стендап», «ежедневно».

**Даты** понимает по-человечески: сегодня, завтра, послезавтра, в пятницу, в следующую
пятницу, через два часа, через полчаса, на следующей неделе, до конца недели, к пятнице,
20 октября, «двадцать третьего ноября», в 3 дня, в 7 вечера, в полдень.

Кроме разговора есть и обычный интерфейс по макету:
- **«Мои задачи», «Встречи», «Напоминания»** — все записи с выбором периода: «Все»,
  «Сегодня», «Неделя», «Месяц», «Просроченные», «Без срока» или свои даты «с … по …»;
- **календарь на месяц**;
- **история разговора**;
- **поиск по Ctrl+K**;
- **колокольчик** с напоминаниями на сегодня;
- **регистрация**: записи доступны с любого устройства, а всё, что гость успел создать
  до регистрации, переезжает в аккаунт.

## Как устроено

Голос целиком на стороне браузера: распознавание и озвучка через Web Speech API. Сервер
получает и возвращает только текст, поэтому его можно проверять и без микрофона.

```
браузер: микрофон → текст ──► FastAPI ──► понимание фразы ──► диалог ──► SQLite
браузер: озвучка ◄── ответ ◄──────────────────────────────────┘
```

- `app/nlu/` — понимание фразы. `text.py` разбивает текст на слова, переводит числа словами
  в цифры и приводит слова к начальной форме (pymorphy3). `dates.py` разбирает даты и время.
  `rules.py` определяет, что хочет пользователь, и вытаскивает название. `llm.py` —
  необязательный разбор через LLM; на выходе та же структура, что и у правил.
- `app/assistant.py` — сам диалог: чего не хватает и что спросить, какую запись менять,
  есть ли пересечения встреч.
- `app/memory.py` — память разговора: о какой записи шла речь («её»), незаконченный вопрос,
  прошлый запрос для реплик вроде «а на завтра?». Хранится в базе, поэтому переживает
  перезагрузку страницы и перезапуск сервера.
- `app/search.py` и `app/semantic.py` — поиск: начальные формы слов, синонимы, нечёткое
  совпадение и семантический слой на эмбеддингах (локальная модель, без внешних API).
- `app/storage.py` — SQLite: записи, история переписки, контекст диалога, пользователи.
- `app/auth.py` — регистрация и вход: пароль хранится только в виде хэша scrypt, сессия —
  в HttpOnly-cookie, есть защита от перебора.
- `app/seed.py` — импорт CSV из задания.
- `static/` — интерфейс без фреймворков: страница входа и приложение.

## Почему так

- **Python + FastAPI** — для русского языка у Python лучшие инструменты, а FastAPI сам
  генерирует документацию API на `/docs`.
- **Голос в браузере** — бесплатно, без ключей, текст появляется прямо во время речи.
  Минус: в Firefox распознавания речи нет, там можно писать текстом.
- **Правила + необязательная LLM.** Правила на начальных формах слов покрывают все сценарии
  из задания и работают мгновенно и без интернета, поэтому прототип можно проверить без
  ключей. LLM подключается для нестандартных формулировок, а правила остаются запасным
  вариантом. С данными в любом случае работает обычный код, LLM только разбирает фразу.
- **SQLite** — не требует настройки, для прототипа хватает с запасом.

## Что решил сам

- В CSV нет типа записи, поэтому определяю его по тексту. «Встреча…», «Созвон…», «Демо…» и
  «Провести планёрку…» — встречи, «Напомнить…» — напоминания, остальное — задачи.
- В тестовых данных сломаны падежи («Позвонить Иваном», «Напомнить Анной про аналитике»).
  При импорте я их чиню, чтобы ассистент нормально зачитывал записи. Исходная строка
  сохраняется.
- Встрече нужны день и время, напоминанию — время, задача может быть без срока. Если
  названо только время и оно уже прошло, ставлю на завтра.
- «В пятницу» — ближайшая пятница, «в следующую пятницу» — пятница следующей недели.
  «В 3» без уточнения — это 15:00, «до конца недели» — воскресенье.
- Удаление и встреча, которая пересекается с другой, требуют подтверждения.
- Вслух ассистент читает только первые пять пунктов, полный список — на экране.
  Озвучку можно остановить кнопкой «Стоп» или клавишей Esc.
- Если посреди уточнения сказать новую команду, ассистент не зависает на старом вопросе,
  а выполняет новую.

## Что бы доделал

- Распознавание речи на сервере (Whisper или SpeechKit), чтобы голос работал во всех браузерах.
- Настоящие уведомления о напоминаниях (push или Telegram-бот). Сейчас напоминание только
  сохраняется.
- Синхронизацию с Google Calendar.
- PostgreSQL вместо SQLite, восстановление пароля по почте.
- Приоритеты задач (они есть в макете).
- Перенос одного повтора из серии. Сейчас переносится вся серия целиком.

## Деплой

Есть `Dockerfile` и `render.yaml` для Render (New → Blueprint → репозиторий).

Про бесплатный тариф Render:
- **Семантический поиск выключен.** Модель не помещается в 512 МБ памяти, поиск работает без
  неё (`SEMANTIC_SEARCH=0`).
- **Сервис засыпает.** Через 15 минут без запросов он засыпает, а база при перезапуске
  обнуляется. Workflow `.github/workflows/keepalive.yml` раз в 10 минут будит сервис.
  Браузер хранит резервную копию записей и возвращает её, если база пустая.
- **Аккаунты стираются при каждом новом деплое.** Если зарегистрироваться заново на ту же
  почту, записи вернутся из резервной копии.
